## 1. Verdict

`PARTIAL — one high-value, metadata-decidable structural defect is now anchored to primary standards evidence; the remaining five sub-questions are anchored but under-sourced.`

Concretely:

1. **The single strongest result of this lane is a `contradicts_premise` finding about the local pipeline's time semantics (FD1).** Official GRIB2 encoding standards separate *four* distinct time quantities per forecast record — reference time, data cutoff, forecast time, and the end/length/type of the statistical time interval. The BARAM supplied tables expose only two timestamps, and the in-repo prepared lineage collapses them into a single scalar `lead_hour = (forecast_kst_dtm − data_available_kst_dtm)/1h`. That scalar is a *latency-shifted* lead, not a physical forecast lead, and it carries no temporal-support information at all. This is exactly FD1, and it is decidable by a key/metadata-only audit with **zero fits**.
2. **A second `directly_supported` structural fact makes the temporal-support gap non-hypothetical:** a single operational GFS product file mixes instantaneous, time-averaged, accumulated, maximum and minimum records. Assuming all supplied GFS value columns share one temporal support is therefore an unverified assumption, not a default.
3. **FD4 (missingness as operational state) has strong primary support** from a wind-specific study finding wind-farm data is *missing not at random* with missing patterns related to the forecast output, and from a primary informative-missingness architecture paper. Both mechanisms migrate to BARAM as *mask + time-since-available features and a deterministic fallback transition table*, implementable on the present stack.
4. **FD8 (unobservable future operational state) is not relieved by anything found here.** The literature recommendation to forecast *available* power is already closed in-repo because the official scorer scores *measured* production. This lane adds only a sharper statement of the resulting estimand and an honest statement of why sample reweighting is not automatically licensed.
5. **FD6 is the cheapest deficit on the board** and needs no new research at all: it is a builder-call-graph plus feature-prefix set difference, i.e. pure metadata.
6. Nothing in this lane claims a BARAM effect size, and nothing claims independent confirmation. The 2024 lockbox is consumed; no fresh holdout exists.
7. **[REVISED v2]** After the mid-lane authority change, **no candidate in this lane is rejected for dependency reasons.** Three previously excluded families are re-admitted and ranked 9–11 purely on weak evidence and high cost. The ranking's top eight are unchanged, because the strongest items were never dependency-limited: they are metadata-only structural audits that need no package at all. The authority change therefore **widens the tail without moving the head**, which is itself a useful finding — the binding constraint on this lane is *evidence and time*, not tooling.
8. **[REVISED v2]** The revised external-data rule (no blanket year cutoff; per-row basis-time availability) removes the last eligibility doubt over a public DEM for an elevation-aware grid-reduction rule, but this lane still cannot rank it, because retrieval is outside lane authority and belongs to `V5-EXTERNAL`.

## 5. Source fact → provisional migration hypothesis → local evidence needed

Each block states (a) SOURCE FACT with locator and date, (b) PROVISIONAL BARAM MIGRATION HYPOTHESIS, (c) LOCAL EVIDENCE NEEDED. No block asserts transfer.

### (a) Issue-time vs valid-time vs temporal support, and cycle selection — FD1

**Block A1 — the four-clock separation.**
- (a) SOURCE FACT [`directly_supported`, `SRC-02`, page created 2007-09-21, relied on 2026-08-09]: GRIB2 PDT 4.8 allocates separate octets to the data cutoff (15–17), the forecast time (19–22), and the end of the overall statistical time interval (35–41), all measured relative to the record's reference time.
- (b) PROVISIONAL BARAM MIGRATION HYPOTHESIS: BARAM's `data_available_kst_dtm` is a *declared availability/publication* clock, not the model reference clock; the true physical lead of a supplied row is `forecast_kst_dtm − reference_time`, which exceeds the currently computed `lead_hour` by the (possibly run-dependent, possibly source-dependent) latency `reference_time → data_available_kst_dtm`. If that latency is constant, `lead_hour` is an exact affine relabelling and the defect is cosmetic. If it varies by source, by cycle, or across the 2022–2023 record, then `lead_hour` mixes two physically different quantities and every lead-conditioned transform downstream is estimated on a smeared coordinate.
- (c) LOCAL EVIDENCE NEEDED (**metadata/key-only, no fit, no values**): for each source ∈ {GFS, LDAPS}, tabulate the multiset of `data_available_kst_dtm` clock-times (hour-of-day, and the residue modulo 3 h and 6 h); the joint cardinality `|{(grid_id, forecast_kst_dtm)}|` vs total row count (does any valid time appear more than once?); the distribution of `lead_hour` per source; and whether the set of distinct `data_available_kst_dtm` values per calendar day is constant across the record. A single fixed clock-time (e.g. always D-1 14:00) is strong evidence of a *declared* availability; a set of 4 or 8 distinct UTC-aligned times is evidence of a genuine per-cycle stamp.

**Block A2 — temporal support is a per-variable property.**
- (a) SOURCE FACT [`directly_supported`, `SRC-03` + `SRC-01`, relied on 2026-08-09]: within one GFS f003 file, 701 records are instantaneous, 35 are 0–3 h averages, 5 are accumulations, 1 max, 1 min.
- (b) PROVISIONAL BARAM MIGRATION HYPOTHESIS: some of the ~35 supplied GFS value fields (and possibly some of the ~30 LDAPS fields) are **interval statistics, not instantaneous samples**, and the interval they summarise may be *offset* from the BARAM hour-ending label. The BARAM target is an hourly mean production; an instantaneous wind speed at the hour boundary and a 1-hour mean wind speed over the labelled hour are different predictors with different Jensen-gap behaviour, and the prepared lineage applies the same seven global statistics to both without distinction (`SEC-02`). The unresolved "N8 NWP valid-time convention" gap recorded in the prior lane (`SEC-01` §4/N8, §6.5) is the same defect seen from the feature side.
- (c) LOCAL EVIDENCE NEEDED (**documentation/metadata only**): read the supplied variable dictionary (`info.xlsx` field descriptions) for each of the ~35 GFS and ~30 LDAPS field names and classify each into `{instantaneous, interval-mean, accumulation, extremum, unknown}`; then, for the ones the dictionary leaves ambiguous, a **value-free structural test**: accumulated fields reset at cycle boundaries and are monotone within a cycle, so a per-`(grid_id, run)` monotonicity/reset check on rank order alone separates accumulations from instantaneous fields without any label contact. Record the classification as a frozen table; it is a prerequisite for any lag/shift experiment.

**Block A3 — cycle selection is not "take the newest".**
- (a) SOURCE FACT [`directly_supported`, `SRC-04`, 1983]: LAF ensemble members from earlier initial times "are produced during the normal operational cycle" and a regression filter over them yields *different weights for different lags*.
- (b) PROVISIONAL BARAM MIGRATION HYPOTHESIS: **conditional on Block A1 revealing more than one `data_available_kst_dtm` per `(source, grid_id, forecast_kst_dtm)`**, the current implicit dedup (a single `lead_hour` per row) discards a legally available, complementary member. A lag-indexed pair of features (newest-run value, older-run value, and their difference) is a legal D-1 14:00 input and encodes forecast *stability*, which is a different signal from forecast *level*.
- (c) LOCAL EVIDENCE NEEDED: exactly the duplicate-key count from Block A1. **If the count is 1 everywhere, this candidate is dead on arrival and costs nothing.** That is the value of ordering it after A1.

### (b) Quality control of issued gridded forecasts

**Block B1 — provider QC state was dropped at export.**
- (a) SOURCE FACT [`directly_supported`, `SRC-02`, 2007-09-21]: the GRIB2 statistically-processed template reserves octets 43–46 for "Total number of data values missing in statistical process".
- (b) PROVISIONAL BARAM MIGRATION HYPOTHESIS: the supplied tabular export retains only `(forecast_kst_dtm, data_available_kst_dtm, grid_id, lat, lon, values…)`, so any provider-side quality/missing-count state that existed in the source records is unavailable. Local QC therefore cannot be a *repair* of a known-bad flag; it must be a *reconstruction* from internal consistency. The correct output of that reconstruction is a **flag feature carried alongside the value**, not a silently corrected value, because a silent correction destroys the very state FD4 says must be modelled.
- (c) LOCAL EVIDENCE NEEDED: schema-only confirmation that no QC/flag/count column exists in either issued table; then a value-statistics-only consistency battery that needs no labels — (i) vector consistency: does `speed ≈ sqrt(u²+v²)` hold to numerical tolerance where both are supplied; (ii) level consistency: is geopotential height monotone in pressure level per row; (iii) thermodynamic consistency: is dewpoint ≤ temperature, RH ∈ [0,100]; (iv) temporal step: per `(grid_id, variable)` the distribution of |Δ| between consecutive valid times, flagging the extreme tail; (v) spatial coherence across the 9/16 supplied points at one valid time. Report *counts and rates only*, never joined to `actual_kwh`.
- HONEST GAP: no official QC taxonomy document (e.g. a WMO quality-management guide) was retrieved before the lane stop. The five tests above are the conventional gross-error/internal-consistency/temporal-consistency/spatial-consistency family, but this lane cites **no source** for that taxonomy → treat the *taxonomy* as `insufficient` and the *mechanism* as analyst-chosen and frozen, per SK@v5 clause 4.

### (c) Missing source/run/level/grid as an operational state — FD4

**Block C1 — informative missingness, represented not imputed.**
- (a) SOURCE FACT [`directly_supported`, `SRC-05`, 2020; `SRC-06`, 2018]: wind power data is missing-not-at-random with missing patterns related to the forecast output (`CL-07`); missing patterns are correlated with target labels and can be exploited via an explicit **mask** plus **time-interval-since-last-observation** representation (`CL-09`).
- (b) PROVISIONAL BARAM MIGRATION HYPOTHESIS: FD4's distinction between "whole-source outage" and "single missing cell" is exactly the mask-structure distinction. Migrate as: (i) a **presence bitset** at the granularity `(source, data_available_kst_dtm, grid_id, variable-group)`; (ii) derived state variables `n_present_grid_points_gfs`, `n_present_grid_points_ldaps`, `source_outage_flag`, `hours_since_source_last_present`; (iii) a **deterministic fallback transition table** stating, for each presence pattern, exactly which reduction rule fires (e.g. "if LDAPS wholly absent → GFS-only reduction with an explicit indicator", never "renormalise the mean over survivors silently"). The mechanism channel is that the reduction rule currently *changes the meaning* of the aggregated feature without telling the model that it changed.
- (c) LOCAL EVIDENCE NEEDED (**presence/null mask only, no values, no labels**): the presence bitset cardinality; the run-length distribution of consecutive missing hours per source; the count of distinct presence patterns actually realised; and the join coverage of `(source, grid_id, forecast_kst_dtm)` against the full 72-cell issuance-day lattice. **All of this is decidable before any fit.** Whether the pattern is *informative about the target* requires a later bounded screen with labels and is out of this lane's authority.
- (d) TRANSFER CAUTION: `CL-08` says that **operationally**, retraining on the remaining inputs beat imputing them; that recommendation was measured on *turbine SCADA inputs*, whereas BARAM's operational missingness is in *NWP source rows*. Population and input axes both differ (`§4`). It motivates a "train a reduced-input fallback model per major presence pattern" variant but cannot justify it.

**Block C2 — the architecture does not migrate; the representation does.**
- (a) SOURCE FACT [`directly_supported`, `SRC-06`, 2018]: GRU-D is a recurrent neural architecture.
- (b) PROVISIONAL BARAM MIGRATION HYPOTHESIS: the *architecture* is `BLOCKED_DEPENDENCY` (no `torch`, dependency changes forbidden, `CL-18`). The *representation* — mask channel plus Δt channel as ordinary columns — is fully implementable with `pandas`+`lightgbm`/`xgboost`/`catboost`, all of which additionally have native missing-value routing, which is itself a mask-like mechanism.
- (c) LOCAL EVIDENCE NEEDED: confirm from the builder source whether the current pipeline **imputes** (median/renormalisation) before handing data to the learner, which would *destroy* the learner's native missing-value routing. This is a source-read, no fit.

### (d) Systematic bias correction legal at D-1 14:00 and fitted past-only

**Block D1 — lead-indexed, input-side, past-only correction.**
- (a) SOURCE FACT [`directly_supported`, `SRC-08`, 1972; `SRC-07`, 2011]: MOS is by construction a relation to model variables *at a given projection time* (`CL-11`); recursive KF and analog post-processing reduce systematic **and** random error in 10-m wind speed, and a plain running mean cannot track abrupt regime-driven error change (`CL-12`).
- (b) PROVISIONAL BARAM MIGRATION HYPOTHESIS: apply a **lead-indexed, group-indexed, strictly past-only recursive bias correction to the NWP wind INPUT** before feature construction, rather than to the model output. Three things distinguish this from the already-closed "post-processing of the current representation": it is input-side; it is indexed by `lead_hour` (or by the repaired physical lead from Block A1); and its state is updated recursively from strictly preceding verifications only, so it is legal at the D-1 14:00 gate and needs no future information. The expected channel is that a lead-dependent systematic wind-speed error passes through a convex power curve and becomes a lead-dependent production bias.
- (c) LOCAL EVIDENCE NEEDED: **first** a no-fit diagnostic — is the repaired lead coordinate from Block A1 even well populated per group (rows per `(group, lead)` cell)? The prior lane already closed *lead-separated training* on sample-count grounds for group 3 (`SEC-01` §6.4: ≈365 rows per lead-time for g3). A recursive filter with one or two states per lead is far cheaper in degrees of freedom than a separate model per lead, but the same counting argument bounds it and must be checked before any fit. **Then** a bounded screen with a strict expanding-origin prequential protocol.
- (d) OVERLAP WARNING: the in-repo lineage already contains a per-cell two-parameter correction (recorded in `SEC-01` §N4 discussion) and an analog family (M252 lineage). Any experiment here must include a control with those *on*, or it will re-measure an effect the pipeline already has.

### (e) Anomaly, outage and curtailment in the TARGET and in sample weighting — FD8

**Block E1 — the estimand under an unobservable state.**
- (a) SOURCE FACT [prior in-repo record `SEC-01` rows E6/E7; `near_match_only` as re-transmitted here]: the wind-forecasting literature recommends deciding explicitly whether curtailed data is kept or removed, and notes that operational availability and control actions change the nature of the power measurement.
- (b) PROVISIONAL BARAM MIGRATION HYPOTHESIS: **this axis is largely closed and should not be reopened in its published form.** FD8 states the future operational state is structurally unobservable at inference under the supplied schema, and the official scorer scores *measured* production on rows with `actual_kwh ≥ 0.10·capacity`. Therefore the estimand is the **mixture** over the unobservable state, `E[y|x] = Σ_s P(s|x)·E[y|x,s]`, and since `P(s|x)` is essentially non-forecastable from `x`, the only legal levers are (i) how anomalous rows are weighted **in training**, and (ii) the action rule under the step reward. Redefining the target to available power is already closed in-repo (`SEC-01` §6.1) and this lane does **not** re-propose it.
- (c) LOCAL EVIDENCE NEEDED: the FD8 smallest diagnostic already specified in the frozen map — a **schema-only** target-definition and operational-field availability receipt confirming that no availability/curtailment/outage field exists in any deployment-symmetric input. That is metadata-only and should simply be executed.
- (d) HONEST LIMIT [`CL-17`, tagged `insufficient`]: reweighting training rows is only a principled correction under a covariate-shift assumption (`p(y|x)` invariant across the weighting). `CL-07` says wind missingness is MNAR, which is precisely the case where that assumption fails. **This lane retrieved no source establishing or bounding the covariate-shift condition**, so the argument above is derived reasoning and is recorded as such. Additionally there is a direct tension a designer must not paper over: curtailed/anomalous rows that satisfy `y ≥ 0.10·cap` **are scored**, so down-weighting them in training moves the fitted action away from the scored population. Any weighting proposal must state which of these two errors it is trading.

### (f) Spatial preprocessing from a sparse supplied grid to farm/group level

**Block F1 — the grid-reduction rule is a choice, and the current one is distance-only.**
- (a) SOURCE FACT [`near_match_only`, prior in-repo record `SEC-01` row E3]: a HEFTCom2024 winning solution included all grid points with no spatial aggregation, and reported that reducing wind inputs to a single point or a spatial mean degraded pinball loss. **Not re-verified at source in this lane; the primary IEEE source on NWP grids (`SRC-11`) could not be fetched.**
- (b) PROVISIONAL BARAM MIGRATION HYPOTHESIS: with only 9 GFS and 16 LDAPS points and 3 groups, "keep all points" is already partly realised in the prepared lineage (44 GFS + 50 LDAPS spatial features, plus seven global statistics per numeric field, `SEC-02`). The remaining lever is therefore **not** "add more points" but (i) whether the per-field spatial allowlist that is narrower than the global payload is leaving structure on the table for non-allowlisted fields, and (ii) whether the reduction weights encode the right axis — on a ridge site the informative axis is cell *terrain elevation*, not horizontal distance.
- (c) LOCAL EVIDENCE NEEDED: **metadata only** — the exact set difference between the spatial allowlist and the full value payload, per source; and confirmation from `configs/`+builder source of which weighting rule is active. Any elevation-aware variant additionally requires an external DEM, which is an `AGENTS.md`-permissible public input but needs its own licence/retrieval receipt and is out of this lane's authority (no downloads).
- (d) OVERLAP WARNING: terrain `mean16`/DEM shading and wake/turbine-level power curves are on the root's closed list. An elevation-weighted *reduction rule* is a different object from a terrain *feature*, but the distinction must be stated explicitly in any node that proposes it, or it will be correctly rejected as a re-proposal.

**Block F2 — FD6: implemented but dormant modules.**
- (a) SOURCE FACT [`directly_supported`, local, `SEC-03`]: FD6 records that the prepare manifest has 820 unique feature names and **zero** `geom__`/`seq__`/`clim` prefixes, i.e. implemented representation modules are absent from the active prepared lineage.
- (b) PROVISIONAL BARAM MIGRATION HYPOTHESIS: before any new spatial preprocessing is written, the highest expected-value-per-unit-cost action on this axis is to determine whether an already-implemented, already-reviewed geometry/sequence/climatology module is simply not wired into the active builder. Activation of existing code is strictly cheaper than new code, has no dependency risk, and cannot be confused with a re-proposal of a closed axis because it is a *lineage* repair, not a *method* claim.
- (c) LOCAL EVIDENCE NEEDED: the FD6 smallest diagnostic verbatim from the frozen map — builder call graph plus exact feature-prefix set difference. **Pure metadata, no fit, no data bodies.**

## 11. DS@v5 / IP@v3 implications

**For `DS@v5` (design synthesis):**

1. **Add a first-class time schema to the node contract.** A single `lead_hour` is not sufficient to describe an issued forecast row (`CL-06`). `DS@v5`'s preprocessing stage should require every issued-weather node to declare, for each supplied field, the tuple `(declared_available_time, inferred_reference_or_cycle, valid_time, support_type, support_interval)` — with `unknown` as a legal, *recorded* value. This makes FD1 auditable rather than latent.
2. **Order the first execution batch as `P1 → P2 → {P3, P4, P5} → P6 → P7 → P8`.** Five of the eight candidates are decided, or killed outright, by metadata-only diagnostics with no fit and no data-body value reads, which fits entirely inside the pre-`IP@v3` authority envelope. `DS@v5` should schedule those five before requesting any fit authority.
3. **Two candidates can close themselves at zero cost** (`P6` on a duplicate-key count, `P5` on a schema enumeration) and one (`P3`) is pure bookkeeping. Scheduling them early raises the information-per-authority-unit of the whole wave.
4. **Escalation path required.** `P5`'s falsifier — discovering a deployment-symmetric availability/curtailment field — would contradict frozen fact FD8. `DS@v5` needs an explicit rule for a Wave-B diagnostic contradicting a root-frozen deficit, since the frozen map is currently treated as authoritative.
5. **Missingness must become a modelled state, not a preprocessing side-effect.** FD4 plus `CL-07`/`CL-09` imply the reduction rule should be a *declared deterministic transition table* stored as an artifact, so that "which rule fired" is reconstructible per row. `DS@v5` should make that table a required node artifact wherever a multi-source reduction occurs.
6. **Degrees-of-freedom accounting.** `P2`'s ±1 h alignment grid, `P7`'s flag thresholds, and `P8`'s adaptation rate are each material analyst choices. Under SK@v5 clause 4 they are admissible but must be frozen and counted before the run, and under FD7 they consume the adaptively-reused development surface. `DS@v5`'s multiplicity contract should budget them explicitly.
7. **The metric axis is the binding scope gap.** Every statistical source in §2 is verified against a continuous error metric; BARAM's is a step-reward action metric. `DS@v5` should require every preprocessing node to state its expected channel in **`1−NMAE` and `FICR` separately**, because the project's recorded failure mode is exactly a candidate that improves point accuracy and damages settlement.

**For `IP@v3` (implementation planning): [REVISED v2]**

1. **No dependency change is needed for candidates `P1`–`P8`.** All eight run on the stack already present (`numpy / pandas / pyarrow / scipy / statsmodels / scikit-learn / lightgbm / xgboost / catboost`). That is now a *cost* advantage rather than a hard constraint.
2. **`BLOCKED_DEPENDENCY` is retired.** The three previously excluded families are re-admitted as `INSTALLABLE` and re-ranked as `P9` (convex metric-aligned weights, `cvxpy`), `P10` (neural informative-missingness, `torch`) and `P11` (distributional/conformal calibration). They rank **9–11 on evidence and cost, not on availability**: `P9`'s justification is unsourced (`CL-17`), `P10` is dominated on FD4 by the far cheaper `P4` and sits adjacent to the closed sequence/issuance axis, and `P11` has **no** source mechanism in this lane and belongs to `V5-MODELS`.
3. **Installing a package is itself a reproducibility obligation.** The rules require reproducibility from submitted code, so any install must be pinned and recorded in the environment manifest before the run that uses it, not after.
4. **`P1`–`P5` need read-only authority over schema, keys and null masks only** — no `actual_kwh`, no predictions, no model results, no 2024, no test-period values. They can be specified now and executed under a narrow grant, and five of them can kill or close themselves with no fit at all.
5. **`P4a` and `P8` require a builder source read and a fit respectively**, so they sit behind `IP@v3` proper.
6. **`P8`'s control set is mandatory, not optional**: the existing per-cell correction and the analog member must both be active in both arms, or the experiment will re-measure an effect the lineage already has — a failure mode this project has recorded before.
7. **External DEM for an elevation-aware reduction rule is now clearly eligible in principle**: public data has no year cutoff, static terrain pre-dates every row's D-1 14:00 KST basis time, and the remaining gates are public accessibility, licence/ToS compliance and reproducibility from submitted code. It was **not** retrieved here and must not be assumed available; retrieval belongs to `V5-EXTERNAL`.
8. **Pretrained weights are a separate, stricter gate (`CL-19`)**: release on or before 2026-07-05, a licence permitting use, modification, distribution, **redistribution** and **commercial** use, and **local** execution only. This lane verified **no** weight against that gate; treat any weight-based preprocessing proposal as `insufficient` until `V5-EXTERNAL` clears it.
9. **Unchanged prohibitions to carry into `IP@v3`**: no reanalysis products, no post-hoc corrected observations, no test-period observations, no evaluation answers, and no remote API model inference.
