## 1. Verdict

**Ten end-to-end pipelines were assessed. Exactly one class is documented in enough stage-by-stage detail to migrate (the HEFTCom2024 winner + runner-up family), and its documented accuracy advantage over what BARAM already has is approximately zero.** The three documented sources of that pipeline's margin are (a) an *additional* NWP source, (b) *coverage / robustness under input outage*, and (c) a *pinball* objective. (a) is closed for BARAM by prior evidence, (c) is not BARAM's metric, and only (b) maps onto a live, unrelieved BARAM deficit (**FD4**).

Three structural findings dominate this lane:

1. **No source in the bound uses a discontinuous step/band settlement metric.** Every one of the ten uses pinball, CRPS, Winkler, RMSE, MAE or NMAE. There is therefore **no metric-matched end-to-end pipeline in the literature reachable within this bound**, and no winner's stage ordering can be assumed optimal for `Total = 0.5*(1-NMAE) + 0.5*FICR`. `[directly_supported]` for the metric list; `[insufficient]` for the existence of any metric-matched pipeline outside the bound.
2. **The HEFTCom2024 winner's own Table 1 contradicts the standard reading of its own headline architecture.** Stacked per-source CatBoost = 28.5 pinball at 100% coverage; the same models concatenated into a single CatBoost with no lagged target = 28.6 at 93.2% coverage. The stack bought **coverage, not accuracy**. `[directly_supported]`
3. **The organisers' cross-team analysis says component *presence* did not separate winners; the *selection protocol* did.** Top teams selected features from training/validation experiments or feature importance; lower-ranked teams selected from exploratory data analysis. `[directly_supported]`

Consequence for BARAM: the highest-value migration from this lane is **not a model component**. It is two *protocol* components (deployment-locked validation atom; selection-provenance registry) plus one *availability* component (per-source base models used as a deterministic fallback ladder). All three are testable with **zero fits** as their first step, and all three are implementable with the frozen local stack.

Nothing in this lane claims a BARAM expected gain. No winner's reported score is transferred.

## 5. Source fact -> provisional migration hypothesis -> local evidence needed

Each block gives (a) SOURCE FACT with locator, (b) PROVISIONAL BARAM MIGRATION HYPOTHESIS, (c) LOCAL EVIDENCE NEEDED. Hypotheses are provisional. None claims transfer or gain.

### H1 — Availability ladder with cross-source quantile/point imputation (FD4, FD5)

**(a) SOURCE FACT.** B3 + O4 + G7 (S4 §3.1/§4, S1 §3, S5 §5.1). The winner drops any X-row with a missing value, so per-source base forecasts vanish under outage; the meta-model then fills the missing base outputs **quantile by quantile from the available base models**, which "allowed us to produce a complete set of reliable forecasts ... even though data coverage was well below 100% for all weather models". Coverage difference in Table 1: 100% (stacked) vs 93.2% (concatenated). Source-level missingness rates 0.3%/1.5%/1.8% (B4). GEB independently supplemented missing GFS with DWD (G7).

**(b) PROVISIONAL MIGRATION HYPOTHESIS.** BARAM's champion consumes GFS and LDAPS in one feature table. Under a whole-source or whole-run outage, that table has a structurally different missingness pattern than under a single missing cell (exactly FD4's stated mechanism), and any median/renormalisation fallback silently converts a *source outage* into an *imputed value*. Hypothesis: replacing the implicit fallback with an **explicit two-arm availability ladder** — arm A = both sources present, arm B = GFS-only, arm C = LDAPS-only, combined by a fixed, pre-declared arbiter — changes the deployed action **only on outage rows**, and therefore has a bounded, countable, pre-computable exposure.

**Re-proposal justification (required, because "GFS/LDAPS source separation" is on the closed list).** This is **not** re-proposed as an accuracy ensemble. B6 and X4 say the accuracy channel is a wash when the domain is small, which is consistent with BARAM's existing closure and I do not contest it. What is new is (i) a **direct source mechanism** never cited in the closure — coverage 100% vs 93.2% and the explicit quantile-wise gap-fill rule — and (ii) a **new local deficit**, FD4, which did not exist as a frozen deficit when source separation was closed. The claim under test is availability, not accuracy.

**(c) LOCAL EVIDENCE NEEDED.** (1) A **zero-fit presence bitset** over the issued tables: for each (issuance day, group, target hour, source), the presence/null mask only — never a value. (2) The **count** of 72-cell issuance days on which at least one source is wholly or partly absent, and the **count** of cells affected. (3) The **deterministic fallback transition table** that the current prepare path actually executes on those rows (read from source, not inferred). If the affected-cell count is negligible, H1 dies at step (1) with no fit spent. This is FD4's own `smallest_diagnostic`, so the diagnostic is already licensed by the frozen map.

### H2 — Deployment-locked validation atom: fix reference time and lead-time window in every fold (FD1, FD3, FD7)

**(a) SOURCE FACT.** G4 + G1 (S5 §3.2, §3.6, §5.1): "The test set is constructed to ensure consistency with the data quality encountered in online testing. Specifically, the reference time for the test set is fixed at 00:00, with a lead time ranging from 23 to 47 hours." Their FLT filter is justified by the *submission gate*, not by accuracy: "the latest available FLT at the time of daily forecast submissions typically range from 23 to 47 hours. Including NWP data with FLT less than 23 hours can enhance forecast accuracy" — i.e. shorter leads help but are **not available**, so they are excluded from the test set on purpose. Reinforced by B15 (the winner naming per-issue-time availability under overlapping issuance as the unsolved practical problem).

**(b) PROVISIONAL MIGRATION HYPOTHESIS.** BARAM's frozen surface fixes one basis time (D-1 14:00 KST) and 24 valid hours, so each of the 72 cells has a *deterministic* lead time in roughly the 11-34 h range. FD1 states that forecast reference/run, declared availability, valid time and temporal support are not separated in the current pipeline. Hypothesis: if any training or validation row is built from a run/lead combination that would not have been available at D-1 14:00 KST for that valid time, then (i) the strict prequential estimate is optimistic in a lead-dependent way, and (ii) the optimism is **concentrated in the early target hours** (shortest lead), which are also disproportionately represented in the FICR band-hit population. Treatment: a per-cell `(source, forecast_reference_time, data_available_kst_dtm, lead_hours)` contract asserted at prepare time and re-asserted per fold.

**(c) LOCAL EVIDENCE NEEDED.** A metadata-only key audit: for each source, the joint distribution of `(forecast_reference_time, data_available_kst_dtm, forecast_kst_dtm)` restricted to rows admitted by the current prepare path, expressed as **counts and uniqueness**, with the derived `lead_hours` histogram **per target hour**. Falsifier: if `data_available_kst_dtm <= D-1 14:00 KST` holds for 100% of admitted rows and `lead_hours` is single-valued per (target hour, source), FD1 is a documentation gap rather than a contamination risk and H2 collapses to a contract test.

### H3 — Selection-provenance registry: record *how* each feature/model choice was selected (FD3, FD7, FD6)

**(a) SOURCE FACT.** O2 (S1 §3): top teams selected features from training/validation experiments or feature importance; lower-ranked teams from exploratory data analysis — with the organisers stating that method *presence* was common to most teams and therefore did not discriminate. Corroborated by K3 (GEFCom2014's own winner taxonomy has "Generalization ability (preventing overfitting)" as a named column: cross-validation, feature-selection + regularization, or training-data selection) and by G2 (RF ranking followed by explicit *manual* train-test selection, which GEB states plainly rather than hiding).

**(b) PROVISIONAL MIGRATION HYPOTHESIS.** BARAM's FD3 says oracle, leaky, screening and deployable evidence get conflated; FD7 says the 2023 surface is adaptively reused and cannot become a fresh holdout. Hypothesis: the single highest-leverage cheap intervention is to attach a **selection-basis tag** to every admitted feature block and every promoted model choice — one of `{fold-outside score, in-sample score, feature importance, EDA/inspection, physical prior, inherited-unaudited}` — plus the trial count that produced it. This does not improve any score by itself; it makes the multiplicity exposure countable, which is the precondition for any honest claim about the remaining 2023 surface.

**(c) LOCAL EVIDENCE NEEDED.** Build the FD3 diagnostic index (its own `smallest_diagnostic`): population, keys, policy, availability class, artifact hash, contamination class, status — extended with the selection-basis tag and trial count. Then compute the **fraction of the 820 prepared feature names whose admission basis is `inherited-unaudited`**. Falsifier: if that fraction is small and every admitted block traces to a fold-outside comparison, FD7's exposure is already bounded and H3 is bookkeeping only.

### H4 — Coverage as a first-class column of the strict receipt, and a priority-ordered model ladder (FD5, FD4)

**(a) SOURCE FACT.** B1 + B2 + B16 (S4 Table 1 and §4): the winner reports **pinball *and* coverage** for every model set, deploys them in a **declared priority order**, and deliberately puts a marginally worse but less input-dependent model first. Their simplest fallback (linear quantile regression) was the *least* available because unseen weather values were rejected. O7 (S1 §5): of the top 15 teams, nine missed no submissions and missed submissions tracked abandonment.

**(b) PROVISIONAL MIGRATION HYPOTHESIS.** FD5 says pooled Total delta hides NMAE/FICR trade-offs, equal-group effects and 6%/8% tier migration. Hypothesis: the strict receipt should expose, alongside Total, a **coverage/count block** (rows scored, rows dropped by the `actual_kwh >= 0.10*capacity` valid-row rule, rows where a fallback arm produced the action) and a **tier-migration block** (cells crossing the 6% and 8% boundaries). Without those, two candidate pipelines with identical Total but different fallback exposure are indistinguishable, and H1 cannot be adjudicated at all.

**(c) LOCAL EVIDENCE NEEDED.** A **contract test** (no fit, no score) asserting that the strict prequential receipt schema exposes component/group/fold/lead/regime/boundary/tier/count/alignment/policy/fit-surface fields. This is verbatim FD5's `smallest_diagnostic`. Falsifier: the fields already exist, in which case H4 is closed as satisfied.

### H5 — Grid-point columns vs spatial order statistics: a bounded representation question (FD6)

**(a) SOURCE FACT.** B10 + B11 + B9 (S4 §3.2) vs G1 + G2 (S5 §3.2). Two top-5 teams took **opposite** decisions on the same axis and both scored well. The winner used **all grid points as separate columns** (X ~ 1000 columns) and measured that collapsing to a spatial mean cost only **~1%** of wind pinball and to a single central point **~2%**; within the best sub-group only 13 of 31 points had importance > 0.5%, with no geographical pattern. GEB reduced the grid to **mean/max/min/p25/p75** and then to a **9-column** wind feature set, and finished 4th.

**(b) PROVISIONAL MIGRATION HYPOTHESIS.** BARAM has 9 GFS + 16 LDAPS points and a prepared surface of 820 feature names. Hypothesis: the grid-reduction axis is **low-amplitude and two-sided** — both the maximal (all points as columns) and the minimal (order statistics) representation are consistent with top-5 performance, so the expected magnitude of any BARAM change on this axis is small relative to the gap to 0.660000. This hypothesis is offered mainly as a **de-prioritisation argument**, not as a build.

**(c) LOCAL EVIDENCE NEEDED.** A zero-fit prefix audit of the existing prepared feature names: which of {per-point columns, order statistics, spatial mean} are already present, and in what proportion. FD6's own diagnostic is "builder call graph plus exact feature-prefix set difference". Falsifier for building anything here: if the prepared surface already contains both per-point and order-statistic forms, the axis is already spanned and no experiment is warranted. **Caution:** this must not be allowed to re-open `vertical PCA` or `terrain mean16`, both on the closed list; the axis here is horizontal grid-point reduction only, and even that is ranked last.

### H6 — Lag-window structure of NWP inputs (FD6)

**(a) SOURCE FACT.** B11 (S4 §3.2): for the best wind model, **lagged wind-speed features carry 64% of total importance, raw 30%, and differenced features ~0%**; lags used were +/-1 and +/-2 samples (half-hourly), i.e. +/-30 and +/-60 minutes. G2 (S5 §3.2): GEB's entire wind feature set is {max, mean, min} x {t-1, t, t+1} at hourly-equivalent spacing. B9: the winner lagged **only wind speed** for the wind models, not all variables.

**(b) PROVISIONAL MIGRATION HYPOTHESIS.** A narrow temporal window (+/-1 to +/-2 steps) on **wind speed only** is the converged choice of two independent top-5 teams, and the differencing operator is measured worthless in the one place it was measured. Hypothesis: if BARAM's prepared surface lacks a +/-1 h wind-speed window on the *issued* tables, adding exactly that (and nothing else) is the smallest representation change with two independent precedents.

**(c) LOCAL EVIDENCE NEEDED.** Same zero-fit prefix audit as H5: does the prepared surface already contain lagged/leading wind-speed columns at +/-1 h per source and grid point? Falsifier: if yes, H6 is already implemented and closes immediately. Note that **importance is not a score gain** — B11 is an importance decomposition inside one fitted model, not an ablation, so H6 can never be promoted on B11 alone. `near_match_only` for the transfer step.

### 7.3 Smallest discriminating local experiment per surviving candidate

**H2 (rank 1) — deployment-locked validation atom**

## 9. DS@v5 / IP@v3 implications

**For `DS@v5` (design synthesis):**

1. **Order the portfolio protocol-first.** This lane's ranking puts three zero-fit protocol/measurement nodes (H2, H4, H3) above every model-side candidate. That is not a stylistic preference: O2 says component presence did not separate HEFTCom winners and selection protocol did, and G4 shows the 4th-place team spending explicit design effort on making the test set match deployment availability. `DS@v5` should schedule H2 and H4 **before** any node that consumes a fit, because H4 is the precondition for adjudicating H1 and H2 is the precondition for trusting any strict comparison at all.
2. **Add a `coverage` and `availability_class` field to the node schema.** SK@v5's required node schema already demands data availability / chronology / licence checks. S4's Table 1 shows a winner ranking models by input-dependency risk rather than score; BARAM's node schema should be able to express that a candidate is *worse on Total but strictly more available*, which it currently cannot.
3. **Record the re-proposal rule.** H1 re-enters an axis on the closed list. `DS@v5` should adopt the explicit test used here: a closed axis may be re-entered only with (i) a named new direct source mechanism and (ii) a named new local deficit, both cited, and only on the specific channel that is new. The accuracy channel of source separation stays closed.
4. **Treat "no metric-matched pipeline exists" as a first-class design fact.** X1 means BARAM cannot inherit a stage ordering. Every stage ordering used so far is inherited from pinball/RMSE literature. `DS@v5` should state this explicitly rather than implying benchmark provenance for the current architecture.
5. **FD2 and FD8 receive no relief from this lane.** FD8 is in fact *reinforced*: every source that successfully handled a capacity/curtailment event did so with a market availability declaration (REMIT/BOA) issued before gate closure, which BARAM structurally lacks. `DS@v5` should record FD8 as confirmed-unobservable under the supplied schema, not as an open research axis.
6. **Multiplicity budget.** The four surviving candidates propose, in total, **0 fits at the diagnostic rung**, at most **1 bounded screen** (H1), and at most **2 strict confirmations** (H1, H2), with 1 degree of freedom each. That is a small enough budget to be honestly accounted against the already-adaptive 2023 surface (FD7). Any expansion beyond it should be rejected on FD7 grounds.
